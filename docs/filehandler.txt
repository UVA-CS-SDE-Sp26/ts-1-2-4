File Handler Plan (Team B)

Responsibility
- Own all direct file system access for mission data files.
- Provide program control a clean API: list available files and return contents.
- Keep data folder location flexible (project root /data or working‑dir /data).

Inputs
- Requests to list files.
- Requests to read a file by index or filename.

Outputs
- Sorted list of filenames.
- Raw file contents as a String (via Optional).

Interface
- class FileCatalog
  - List<String> listFiles()
  - Optional<String> getByIndex(int index)
  - Optional<String> getByName(String filename)
- class FileReaderService
  - String readFile(String path) throws IOException

Behavior
- Resolve data directory in this order:
  1) ./data (project root).
  2) ./build/../data if running from build (fallback).
  3) working‑dir/data (same folder as program).
- If no data directory is found, warn on stderr and default to ./data.
- listFiles() refreshes the cached list each call, returns sorted filenames
  (case‑insensitive) without indices.
- getByIndex() maps 1‑based input into the cached list and reads by filename.
- getByName() builds a full path and reads the file contents.
- readFile() returns raw file contents (no decipher here) or throws IOException
  if the path is missing or a directory.

Error Handling
- If data directory missing: print a warning; listFiles() may return empty.
- If file cannot be read: log to stderr in FileCatalog and return Optional.empty().
- FileReaderService throws IOException for missing paths or directories.

Storage Notes
- Mission text files are expected in the `data/` directory at project root.
- The path resolution order allows running from IDE, command line, or Gradle without hardcoded absolute paths.

Testing Ideas (TDD)
- listFiles() on empty data dir returns empty list.
- listFiles() returns sorted order without indices.
- getByIndex() with invalid index returns empty Optional.
- getByName() returns empty Optional on read error.
- readFile() returns exact file contents or throws IOException.
