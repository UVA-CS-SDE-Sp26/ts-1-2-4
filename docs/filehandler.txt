File Handler Plan (Team B)

Responsibility
- Own all direct file system access for data files.
- Provide program control a clean API: list available files and return contents.
- Keep data folder location flexible (project root /data or working‑dir /data).

Inputs
- Requests to list files.
- Requests to read a file by index or filename.

Outputs
- Sorted list of filenames.
- Raw file contents as a String.

Interface (proposed)
- class FileCatalog
  - List<String> listFiles()
  - Optional<String> getByIndex(int index)
  - Optional<String> getByName(String filename)
  - String dataDir
- class FileReaderService
  - String readFile(String path)

Behavior
- Resolve data directory in this order:
  1) ./data (project root).
  2) ./build/../data if running from build (fallback).
  3) working‑dir/data (same folder as program).
- listFiles() returns sorted filenames (case‑insensitive) with 1‑based indices.
- getByIndex() maps the user number to the sorted list.
- readFile() returns raw file contents (no decipher here).

Error Handling
- If data directory missing or empty: return empty list and a descriptive error.
- If file cannot be read: return an error message to program control.

Testing Ideas (TDD)
- listFiles() on empty data dir returns empty list.
- listFiles() returns sorted order and 1‑based indices.
- getByIndex() with invalid index returns empty.
- readFile() returns exact file contents.
